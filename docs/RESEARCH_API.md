# Research / Evidence: первый рабочий слой, 30.09.2026

По поручению Али «следующий шаг» реализуется приватное исследование задачи. Исходное видение — RESEARCH_EVIDENCE.md. Веб-поиск запускается кнопкой после проверки короткого запроса; автоматического поиска при каждом сообщении нет. Только этот запрос передаётся поисковому инструменту, полный профиль и переписка не передаются ему. Связь результатов с карточкой и последними сообщениями выполняется отдельным AI-вызовом без инструментов. Используется существующий серверный ключ, модель OPENAI_RESEARCH_MODEL либо OPENAI_MODEL. Нужен доступ этой модели к Responses web_search; сбой показывается явно.

- GET /api/me/tasks/{id}/research?locale=ru|en — BUSINESS-владелец, no-store; последняя завершённая подборка, актуальный запуск, сохранённые выводы, текущие данные бизнеса. Для подборки/сохранённых выводов возвращается stale при изменении карточки. После суток — expired; автоматического платного обновления нет.
- POST того же пути: {query:10..500,locale,expected_revision,refresh:false}. CSRF, проверка revision и владения. Совпадающий query+карточка+locale в пределах суток использует кэш. refresh запускает новый поиск. Один активный поиск на аккаунт, до 6 запусков в час. Один запуск имеет тайм-аут 100 секунд; зависший помечается failed через 150 секунд. Ошибка не стирает прежний результат. Результат сохраняется даже после ухода из раздела; при изменении карточки помечается устаревшим.
- POST /api/me/tasks/{id}/evidence: {run_id,insight_index}. Сохраняет вывод завершённого исследования этой же задачи, идемпотентно, до 20 записей. DELETE /api/me/tasks/{id}/evidence/{evidence_id} удаляет его из личной доски. Карточка, подтверждения и рейтинг не меняются. Сохранённые выводы сохраняют исходный язык/дату/ссылки.

Первый AI-вызов — Responses с обязательным web_search, до 3 вызовов инструмента и 2500 токенов результата. Только URL из реальных url_citation аннотаций могут стать источниками; HTTP(S), без локальных адресов или учётных данных. Сохраняются заголовок, домен и дата доступа. Фрагмент — дословная часть ответа поиска рядом с цитированием, НЕ дословная цитата статьи. Дата публикации не выдумывается; если API её не дал, показывается «не указана». Пустая выдача — честный результат без источников, ошибка инструмента — ошибка.

Второй вызов сопоставляет до 12 фрагментов с данными задачи: до 3 факторов, ID фрагментов и исходных пользовательских фраз, категория scientific/industry/solution/other, связь с задачей, гипотеза, ограничения применимости и следующий вопрос. Все ID проверяются сервером; новые URL/«факты бизнеса» модель создать не может. Категория — AI-классификация, не гарантия научной проверки. Ссылки показываются непосредственно рядом с каждым выводом.

FACT — внешний вывод с указанным источником и пометкой, что его пересказ подготовлен AI; это не доказанная причина на предприятии. BUSINESS DATA — дословные сведения пользователя, ручное подтверждение отмечается отдельно. Общая цель или название задачи не допускаются в качестве сведений о конкретном факторе. HYPOTHESIS — предположение для проверки. Устаревшие сохранённые выводы не передаются агенту. Актуальные передаются отдельным контекстом только для уточняющих вопросов и не входят в допустимые источники полей карточки. В последующих репликах вопросы на текущем языке ограничиваются сохранёнными исследовательскими вопросами, если они есть; агент может пропустить их, если они уже отвечены, ответ неизвестен или пользователь обсуждает другую тему. Первый ответ сохраняет прежние три уточнения. Пользователь отвечает сам; модельные выводы не вставляются от его имени в чат.

RU/EN, компактный вход из чата, отдельный экран с категориями, состояниями поиска/ошибки/пустой выдачи, Evidence Board, сохранение после reload. Публичная публикация исследований, автоматический мониторинг источников, загрузка полных статей и граф связей остаются следующими итерациями. Документация инструмента: https://developers.openai.com/api/docs/guides/tools-web-search .
