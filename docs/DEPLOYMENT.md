# Публикация SOLVEX на Vercel

## Архитектура

Vercel обслуживает FastAPI (`app/main.py`) и файлы `web/`. Аккаунты, фото,
сообщения, квоты и проекты хранятся в отдельной удалённой **libSQL** базе Turso.
Используется remote-only драйвер, без локальной реплики или синхронизации файлов.
Локальная разработка по-прежнему использует `data/hackalem.db`.

В Vercel приложение намеренно отказывается запускаться без облачной базы.
Копирование SQLite в `/tmp` не является постоянным хранением.

## Настройка

1. Импортировать `gitaliuer/SOLVEX` в свой Vercel. Корень проекта — корень
   репозитория; framework FastAPI, Python 3.12. Итоговая ветка должна содержать
   текущий релиз, а не старую загрузку файлов.
2. Подключить отдельную **libSQL** базу через Turso Cloud. Не выбирать новый
   движок Turso Database для этого драйвера. Подтвердить условия и стоимость
   выбранного плана; не включать платные опции автоматически.
3. Установить в серверных переменных Vercel:
   `APP_ENV=production`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`,
   `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-4.1-mini-2025-04-14`.
   `OPENAI_RESEARCH_MODEL` необязателен. Секреты не добавлять в Git,
   клиентский JavaScript, логи, публичные ссылки или документы.
4. Production и Preview должны иметь разные базы. Не назначать production
   секреты всем preview-веткам; альтернативно оставить Preview без секретов.
5. Выполнить deploy. Время функции 180 секунд покрывает текущий Research,
   который ожидается внутри запроса. Приложение не запускает AI через
   недолговечные фоновые задачи после завершения ответа.

## Проверка после deploy

- Главная, `/static/*`, `/api/health` возвращают 200; `/api/me/tasks` без
  сессии — 401; старые `/api/tasks`, `/api/teams`, `/api/proposals` — 404.
- Регистрация, вход, HttpOnly/Secure-cookie, CSRF и разделение ролей работают.
- Создать учебную задачу и убедиться, что она читается новой сессией после
  повторного deploy. Проверить фото, отклик, сообщение и этап проекта.
- Проверить настоящий AI-вызов и Research с серверным ключом, списание квоты,
  чтение результата и сохранность истории.
- Настроить бюджет AI, мониторинг ошибок и резервирование облачной базы.

## Данные и выпуск

Облачная база создаётся пустой. Локальная база с аккаунтами и черновиками
не копируется в Git или облако автоматически; перенос — отдельная операция
с резервной копией и проверкой доступа. В production не создаются синтетические
примеры и закрывается прежнее общее demo API. Личный контур и каталог сохраняются.

Наличие `vercel.json` не подтверждает успешную публикацию. URL, коммит,
готовность базы и результаты внешних проверок фиксируются после реального deploy.
Оплата подписки по-прежнему не подключена.
