# SOLVEX — от проблемы к решению

SOLVEX помогает бизнесу превратить проблему в понятную задачу, а командам — предложить свой подход. Главная страница, регистрация и кабинет работают на русском языке. AI уточняет сведения и предлагает карточку; факты, публикацию и выбор команды подтверждает человек.

## Что работает сейчас

- Первый экран с геометрическим SVG-логотипом, интерактивной графикой, примерами задач и адаптивной вёрсткой. Анимация отключается кнопкой или системной настройкой уменьшенного движения.
- Регистрация BUSINESS / TEAM, вход, выход, серверные сессии, Argon2id, CSRF и ограничение неверных попыток входа.
- Бизнес: личные черновики, вопросы AI, редактирование, ручное создание карточки, рейтинг, публикация и повторное открытие той же задачи.
- Команда: собственный профиль, поиск и фильтры каталога, отправка отклика, просмотр решения бизнеса.
- Бизнес вручную выбирает одну, несколько или ни одной команды. Подтверждение этапа даёт команде +10 баллов однократно.

Черновик видит только его автор. После публикации все поля карточки, включая контакт бизнеса, открываются в каталоге. Начальные синтетические записи старой версии в новом интерфейсе не показываются: каталог наполняют зарегистрированные пользователи.

## Локальный запуск: Windows PowerShell

Нужны Git и Python 3.12. Если проект уже открыт локально, используйте его папку SOLVEX. Для новой копии:

```powershell
git clone https://github.com/gitaliuer/SOLVEX.git solvex-review
cd solvex-review
```

Новый интерфейс подготовлен в ветке `feat/solvex-experience` поверх аккаунтов `b730220`; до объединения с main переключитесь на эту ветку:

```powershell
git switch feat/solvex-experience
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

Если `py` отсутствует, используйте `python -m venv .venv`. Окружение активировать необязательно.

Для живого AI заполните `OPENAI_API_KEY` в локальном **файле `.env`**. Ключ читает только сервер; `.env` исключён из Git. Модель задаётся `OPENAI_MODEL`. Значения переменных окружения AI имеют приоритет над файлом. Не помещайте ключ в браузер или исходники.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

Оставьте терминал открытым и перейдите на [главную](http://127.0.0.1:8000/). Остановка — `Ctrl+C`. После изменения кода или настроек перезапустите сервер; при занятом порте используйте `--port 8001`.

База по умолчанию — `data/hackalem.db`, она исключена из Git. Аккаунты, профили, задачи и отклики сохраняются между запусками. Обновление существующей БД добавляет владельцев и таблицы аккаунтов, сохраняя прежние записи.

## Первый рабочий сценарий

1. Нажмите «Обсудить задачу» и зарегистрируйтесь как бизнес.
2. Укажите тему и описание. Получите вопросы AI либо нажмите «Заполнить карточку самому».
3. Исправьте карточку, подтвердите известные сведения и сохраните. Она появится в «Моих задачах».
4. Опубликуйте задачу. Низкий рейтинг не мешает публикации.
5. В другом профиле браузера создайте аккаунт команды и заполните её профиль. Найдите задачу в каталоге и отправьте предложение.
6. В бизнес-аккаунте откройте «Отклики команд», примите решение и подтвердите выполненный этап.

Каталог, сохранение карточек, профили и отклики работают без AI-ключа. AI без настройки возвращает понятную ошибку, а не заранее подготовленный ответ.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -W error::RuntimeWarning -m unittest app.ai.test_service app.ai.test_review_regressions -v
```

Для браузерного прогона используйте **отдельную базу**: тест создаёт синтетические аккаунты, задачи и отклики. Нужны установленный Playwright для Node.js и Microsoft Edge.

В первом терминале:

```powershell
$env:DATABASE_PATH = "data/ui-rehearsal.db"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8010
```

Во втором:

```powershell
$env:UI_TEST_URL = "http://127.0.0.1:8010"
node web/tests/experience.cjs
```

Тест проверяет реальные аккаунты, повторный вход, сохранение по тому же ID, истечение сессии, публикацию, профиль, отклик, решение и выход. Только AI-ответы в этом прогоне подменяются; доступ к живой модели он не подтверждает. Снимки сохраняются в `%TEMP%\solvex-experience`. Отдельные 19 регрессий редактора доступны на `/static/tests/ui.html`.

## Архитектура и границы этапа

FastAPI отдаёт HTML/CSS/JavaScript и JSON API. SQLite хранит состояние. Публичные маршруты каталога — `/api/catalog/*`, личные — `/api/me/*`, аккаунты — `/api/auth/*`. Контракты и права доступа описаны в [CONTRACTS](docs/CONTRACTS.md).

Рейтинг 0–100 отражает полноту подтверждённых полей, а не достоверность данных или гарантированный результат. AI может ошибаться: человек проверяет и подтверждает карточку.

Текущий AI выполняет два действия: уточняющие вопросы и формирование карточки. Постоянная история диалога, подбор команд, анализ предложений и проектная дорожная карта — следующие этапы, описанные в [PLAN](docs/PLAN.md). Они не имитируются в интерфейсе.

Производственное развёртывание, подтверждение email и восстановление пароля пока не реализованы. Для HTTPS-развёртывания задаётся переменная процесса `APP_ENV=production`, включающая Secure cookie. Старые открытые демо-маршруты сохранены для совместимости и изолированы от записей с владельцем.

История предыдущей демо-версии и её живых AI-проверок: [EVAL](docs/EVAL.md), [сценарий показа](docs/DEMO_SCRIPT.md). Результаты нового этапа приведены в начале EVAL.
