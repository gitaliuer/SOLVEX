# SOLVEX — от проблемы к решению

SOLVEX помогает бизнесу превратить проблему в понятную задачу, а командам — предложить свой подход. Главная страница, регистрация и кабинет работают на русском и английском языках. AI уточняет сведения и предлагает карточку; факты, публикацию и выбор команды подтверждает человек.

## Что работает сейчас

- Первый экран с геометрическим SVG-логотипом, интерактивной графикой, примерами задач и адаптивной вёрсткой. Анимация отключается кнопкой или системной настройкой уменьшенного движения.
- Регистрация BUSINESS / TEAM, вход, выход, серверные сессии, Argon2id, CSRF и ограничение неверных попыток входа.
- Бизнес: AI Agent с постоянной историей диалога, карточка рядом с чатом, готовность, ручное редактирование и подтверждение фактов, публикация и восстановление задачи.
- Подбор команд для опубликованной задачи: объяснения с фрагментами карточки, поиск, личное избранное, переход к откликам. Работает по правилам сопоставления профилей без вызова AI; не выбирает исполнителя.
- Профили компании и команды: фото/логотип, описание, отрасль, город, сайт/портфолио, размер команды, проекты, публичный контакт, навыки команды и живой предпросмотр. Фото проверяется и сохраняется на сервере; после перезапуска остаётся в SQLite.
- RU/EN: переключатель на первом экране и в кабинете. Язык сохраняется в браузере, ввод не теряется; пользовательские тексты не переводятся автоматически. Новые ответы Agent используют выбранный язык.
- Команда: поиск и фильтры каталога, отправка отклика, просмотр решения бизнеса.
- Бизнес: сравнение сроков и навыков команд, отдельный настоящий AI-разбор каждого отклика с дословными проверенными цитатами и вопросами для обсуждения. Разбор сохраняется отдельно для RU/EN и помечается устаревшим при изменении карточки; AI не оценивает вероятность успеха и не выбирает команду.
- Бизнес вручную выбирает одну, несколько или ни одной команды. Подтверждение этапа даёт команде +10 баллов однократно.

Черновик видит только его автор. После публикации все поля карточки, включая контакт бизнеса, открываются в каталоге. Начальные синтетические записи старой версии в новом интерфейсе не показываются: каталог наполняют зарегистрированные пользователи.

## Локальный запуск: Windows PowerShell

Нужны Git и Python 3.12. Если проект уже открыт локально, используйте его папку SOLVEX. Для новой копии:

```powershell
git clone https://github.com/gitaliuer/SOLVEX.git solvex-review
cd solvex-review
```

Новый интерфейс подготовлен в ветке `feat/profiles-and-proposal-review` поверх подбора команд `8fcf097`; до объединения с main переключитесь на эту ветку:

```powershell
git switch feat/profiles-and-proposal-review
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

Если `py` отсутствует, используйте `python -m venv .venv`. Окружение активировать необязательно.

Для живого AI заполните `OPENAI_API_KEY` в локальном **файле `.env`**. Ключ читает только сервер; `.env` исключён из Git. Модель задаётся `OPENAI_MODEL`. Значения переменных окружения AI имеют приоритет над файлом. Не помещайте ключ в браузер или исходники.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

Оставьте терминал открытым и перейдите на [главную](http://127.0.0.1:8000/). Остановка — `Ctrl+C`. После изменения кода или настроек перезапустите сервер; при занятом порте используйте `--port 8001`.

База по умолчанию — `data/hackalem.db`, она исключена из Git. Аккаунты, профили, задачи, сообщения агента и отклики сохраняются между запусками. Обновление существующей БД добавляет таблицы диалога и версии карточек, сохраняя прежние записи.

## Первый рабочий сценарий

1. Нажмите «Обсудить задачу» и зарегистрируйтесь как бизнес.
2. Напишите агенту, что хотите изменить. Он задаст три уточняющих вопроса; отвечайте свободным текстом. Карточка заполняется рядом, история сохраняется. Можно сразу редактировать карточку вручную.
3. Раскройте нужные поля карточки, исправьте текст, подтвердите известные факты и сохраните. Рейтинг пересчитается на сервере. Задача доступна в «Моих задачах»; перезагрузка восстанавливает текущий диалог.
4. Опубликуйте задачу. Низкий рейтинг не мешает публикации. Нажмите «Найти команду» — сравните профили, изучите основания совпадений и сохраните интересных участников в избранное. Новые реальные профили появятся после регистрации команд; демонстрационные записи не подмешиваются.
5. В другом профиле браузера создайте аккаунт команды и заполните её профиль. Найдите задачу в каталоге и отправьте предложение.
6. В бизнес-аккаунте откройте «Отклики команд», примите решение и подтвердите выполненный этап.

Каталог, сохранение карточек, профили и отклики работают без AI-ключа. AI без настройки возвращает понятную ошибку, а не заранее подготовленный ответ.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -W error::RuntimeWarning -m unittest app.ai.test_service app.ai.test_review_regressions -v
```

Для браузерного прогона используйте **отдельную базу**: тест создаёт синтетические аккаунты, задачи и отклики. Нужны установленный Playwright для Node.js и Microsoft Edge.

В первом терминале:

```powershell
.\.venv\Scripts\python.exe -m web.tests.agent_server
```

Во втором:

```powershell
$env:UI_TEST_URL = "http://127.0.0.1:8010"
node web/tests/experience.cjs
node web/tests/matching.cjs
```

Тест проверяет реальные аккаунты, повторный вход, сохранение по тому же ID, истечение сессии, публикацию, профиль, отклик, решение и выход. Тестовый сервер сам создаёт временную БД и подменяет только AI-ответы; доступ к живой модели он не подтверждает. Снимки сохраняются в `%TEMP%\solvex-experience`. Отдельные 15 регрессий интерфейса доступны на `/static/tests/ui.html`.

## Архитектура и границы этапа

FastAPI отдаёт HTML/CSS/JavaScript и JSON API. SQLite хранит состояние. Публичные маршруты каталога — `/api/catalog/*`, личные — `/api/me/*`, аккаунты — `/api/auth/*`. Контракты и права доступа описаны в [CONTRACTS](docs/CONTRACTS.md).

Рейтинг 0–100 отражает полноту подтверждённых полей, а не достоверность данных или гарантированный результат. AI может ошибаться: человек проверяет и подтверждает карточку.

AI Agent ведёт диалог с историей, задаёт вопросы и обновляет черновик по исходным фразам пользователя. Повтор запроса не дублирует сообщение, ошибки видны явно. Ручные правки защищены от устаревшего ответа; опубликованную карточку агент обсуждает, но не меняет. Контракт — [AGENT](docs/AGENT.md). Подбор команд уже доступен по [MATCHING](docs/MATCHING.md): навыки, технологии и направление сопоставляются с карточкой по открытым правилам. Для сложных формулировок совпадение может отсутствовать, поэтому доступны все профили. Анализ предложений и проектная дорожная карта — следующие этапы [PLAN](docs/PLAN.md).

Производственное развёртывание, подтверждение email и восстановление пароля пока не реализованы. Для HTTPS-развёртывания задаётся переменная процесса `APP_ENV=production`, включающая Secure cookie. Старые открытые демо-маршруты сохранены для совместимости и изолированы от записей с владельцем.

История предыдущей демо-версии и её живых AI-проверок: [EVAL](docs/EVAL.md), [сценарий показа](docs/DEMO_SCRIPT.md). Результаты нового этапа приведены в начале EVAL.

Контракт новых профилей, фото, локализации и разбора: [docs/PROFILES_REVIEW.md](docs/PROFILES_REVIEW.md). Фото до 3 МБ (JPEG/PNG/WebP) пересохраняются без метаданных. Для обработки фото зависимость Pillow входит в requirements.txt. Поля профиля и фото публичны; email аккаунта не раскрывается.

Проверка новых экранов на отдельном сервере `python -m web.tests.agent_server`: `node web/tests/profiles.cjs`. Этот сервер использует временную БД и явно синтетические AI-ответы. Рабочий запуск `uvicorn app.main:app` использует настоящий AI.
